# MVMP — Migration: Docker → Native (Phase 14)

This guide walks an operator through migrating an existing MVMP Docker deployment (Phase 14) to a Native Linux deployment (Phase 13), preserving all data.

**Duration**: 45–90 minutes (Native install takes longer than Docker build).

**Downtime**: 5–15 minutes during the final cutover.

**Risk**: Low. Every step is reversible until the source Docker deployment is decommissioned.

---

## 0. Pre-migration checklist

- [ ] Source Docker deployment is healthy: `bash scripts/deploy/docker-health-check.sh` reports all PASS.
- [ ] Target host is Ubuntu 22.04 or 24.04 (verified by `bash scripts/deploy/check-requirements.sh`).
- [ ] At least 10 GB free disk.
- [ ] Operator has sudo on the target host.
- [ ] Maintenance window of 45–90 minutes scheduled.
- [ ] DNS TTL for the public domain is set low (300s).

If source and target are different hosts:
- [ ] SSH between them works.
- [ ] Backup file can be transferred.

If same host:
- [ ] Both modes can coexist (different ports, different volumes — see `DATA_ISOLATION.md`).

---

## 1. Backup the Docker deployment

On the source host:

```bash
cd /opt/mvmp
bash scripts/deploy/docker-backup.sh

# Find the backup
HOST_PATH=$(docker volume inspect mvmp_mvmp-backups --format '{{ .Mountpoint }}')
sudo ls -la "$HOST_PATH/"
# Note the timestamp, e.g. 20260101-030000

sudo ls -la "$HOST_PATH/20260101-030000/"
# Contains: postgres-20260101-030000.dump.gz
```

Note: Docker backup only includes PostgreSQL (no Redis RDB or app config tarball by default). If you want Redis state preserved, run:

```bash
docker compose -f deploy/docker/docker-compose.yml exec redis \
  redis-cli -a "$MVMP_REDIS_PASSWORD" --no-auth-warning bgsave
sleep 5
REDIS_VOL=$(docker volume inspect mvmp_mvmp-redis-data --format '{{ .Mountpoint }}')
sudo cp "$REDIS_VOL/dump.rdb" /tmp/mvmp-redis.rdb
sudo gzip /tmp/mvmp-redis.rdb
```

Also export the env config:

```bash
sudo cp /opt/mvmp/.env /tmp/mvmp-docker.env
```

## 2. Install Native dependencies on the target host

```bash
cd /opt/mvmp   # or wherever the repo lives on target

# Check requirements
bash scripts/deploy/check-requirements.sh

# Install system packages (Node, bun, PG, Redis, Nginx, Certbot)
sudo bash scripts/deploy/install-system-packages.sh

# Configure PostgreSQL
sudo bash scripts/deploy/install-postgresql.sh
# Writes /etc/mvmp/db.env with a NEW random password

# Configure Redis
sudo bash scripts/deploy/install-redis.sh
# Writes /etc/mvmp/redis.env with a NEW random password

# Create mvmp system user
sudo bash scripts/deploy/create-user.sh
```

---

## 3. Reconcile secrets between Docker and Native

**CRITICAL**: For the migration to preserve encrypted AI provider keys, the Native deployment MUST use the SAME `AI_ENCRYPTION_KEY` as the Docker deployment.

```bash
# Read Docker's env (from /opt/mvmp/.env or /tmp/mvmp-docker.env)
DOCKER_AI_KEY=$(grep AI_ENCRYPTION_KEY= /tmp/mvmp-docker.env | cut -d= -f2-)
DOCKER_SESSION=$(grep SESSION_SECRET= /tmp/mvmp-docker.env | cut -d= -f2-)
DOCKER_PUBLIC_URL=$(grep PUBLIC_URL= /tmp/mvmp-docker.env | cut -d= -f2-)
```

Configure Native `/etc/mvmp/app.env`:

```bash
sudo cp .env.production.example /etc/mvmp/app.env
sudo chown root:mvmp /etc/mvmp/app.env
sudo chmod 640 /etc/mvmp/app.env

sudo nano /etc/mvmp/app.env
# Set:
#   AI_ENCRYPTION_KEY=$DOCKER_AI_KEY      (CRITICAL — must match Docker)
#   SESSION_SECRET=$DOCKER_SESSION
#   PUBLIC_URL=$DOCKER_PUBLIC_URL
#   NODE_ENV=production
```

Database and Redis passwords are NEW (generated by `install-postgresql.sh` and `install-redis.sh`). The migration script will rewrite the connection strings in the database dump to match the new credentials.

---

## 4. Transfer the backup to the target host

### Same host

```bash
# Backup is already at $HOST_PATH on source. No transfer needed.
# But Native scripts look in /var/backups/mvmp/. Symlink or copy:
sudo mkdir -p /var/backups/mvmp
sudo cp -r "$HOST_PATH" /var/backups/mvmp/
```

### Different host

```bash
# On source
HOST_PATH=$(docker volume inspect mvmp_mvmp-backups --format '{{ .Mountpoint }}')
scp -r "$HOST_PATH/<timestamp>" target-host:/var/backups/mvmp/

# On target
sudo chown -R root:root /var/backups/mvmp/<timestamp>
sudo chmod 700 /var/backups/mvmp/<timestamp>
```

---

## 5. Build the Native application

```bash
cd /opt/mvmp

# Load the NEW Native env (so prisma can connect to NEW Native PG)
set -a; . /etc/mvmp/db.env; . /etc/mvmp/redis.env; . /etc/mvmp/app.env; set +a

bash scripts/deploy/build.sh
```

This builds Next.js standalone, generates Prisma client for PostgreSQL, and prepares the realtime service.

---

## 6. Restore the Docker backup into Native PostgreSQL

The Docker backup uses `pg_dump --format=custom` which is portable. The user/password in the dump is from Docker's PostgreSQL, but `pg_restore --no-owner --no-privileges` ignores ownership.

```bash
sudo bash scripts/deploy/restore.sh /var/backups/mvmp/<timestamp> --force
```

This script:
1. Takes a SAFETY backup of the (empty) Native PG
2. Stops MVMP services (none running yet on Native)
3. Drops + recreates the `mvmp` database
4. Restores from the dump
5. Starts MVMP services (will fail at this point — we haven't installed systemd yet)

The restore will succeed. The "start services" step at the end may fail because systemd units aren't installed yet. That's OK — continue.

Verify row counts:

```bash
sudo -u postgres psql -d mvmp -c "
  SELECT 'users' AS table, count(*) FROM \"User\"
  UNION ALL SELECT 'servers', count(*) FROM \"Server\"
  UNION ALL SELECT 'vpn_accounts', count(*) FROM \"VpnAccount\"
  UNION ALL SELECT 'conversations', count(*) FROM \"ChatConversation\";
"
```

Counts should match the Docker deployment.

## 7. Apply any pending migrations

The Docker image may have a newer Prisma schema than the backup. Apply pending migrations:

```bash
sudo bash scripts/deploy/migrate.sh
```

This runs `prisma migrate deploy` (non-destructive, non-interactive).

## 8. Install systemd units

```bash
sudo bash scripts/deploy/setup-systemd.sh
```

Installs `mvmp-api.service`, `mvmp-worker.service`, `mvmp-realtime.service` and enables them.

## 9. Start Native services

```bash
sudo systemctl start mvmp-realtime
sudo systemctl start mvmp-api
sudo systemctl start mvmp-worker

# Verify
sudo systemctl status mvmp-api mvmp-worker mvmp-realtime --no-pager
bash scripts/deploy/health-check.sh
```

All checks should PASS.

## 10. Verify the Native deployment

Smoke test:
- Visit `https://mvmp.your-domain.com/` — landing page loads (after Nginx switch in step 11).
- Log in as superadmin → dashboard loads.
- Customer portal → VPN accounts visible (matches Docker).
- Send a chat message → AI replies (or mock fallback).
- Admin → Live Chat → conversations from Docker are visible.

Verify AI provider keys decrypt correctly (the `AI_ENCRYPTION_KEY` match is critical here):

```bash
# Check the AI Center → Providers page
# If keys show "Encrypted" and can be tested successfully, the migration preserved them.
# If keys fail to decrypt, AI_ENCRYPTION_KEY doesn't match — re-import from Docker.
```

---

## 11. Switch Nginx upstream to Native

```bash
sudo nano /etc/nginx/sites-available/mvmp.conf
```

Change upstreams back to Native ports:

```nginx
upstream mvmp_api {
    server 127.0.0.1:3000;     # was 127.0.0.1:3001 (Docker)
    keepalive 32;
}
upstream mvmp_realtime {
    server 127.0.0.1:3003;     # was 127.0.0.1:3005 (Docker)
    keepalive 16;
}
```

Validate + reload:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

Public traffic now flows to the Native deployment.

---

## 12. Stop the Docker deployment

```bash
cd /opt/mvmp
docker compose -f deploy/docker/docker-compose.yml stop
# Containers stop but data volumes remain
```

Optional full decommission (after a confidence period):

```bash
docker compose -f deploy/docker/docker-compose.yml down --remove-orphans
# Volumes still exist
docker volume rm mvmp_mvmp-pgdata mvmp_mvmp-redis-data mvmp_mvmp-backups
# WARNING: removes all Docker MVMP data — only after you're confident in Native
```

---

## 13. Update cron backups

```bash
sudo rm /etc/cron.d/mvmp-docker-backup
sudo cp deploy/cron/mvmp-backup /etc/cron.d/mvmp-backup
sudo chmod 644 /etc/cron.d/mvmp-backup
sudo systemctl reload cron
```

---

## 14. Rollback (if anything goes wrong)

If the Native deployment has issues within the first 24 hours:

```bash
# Stop Native
sudo systemctl stop mvmp-api mvmp-worker mvmp-realtime

# Start Docker
cd /opt/mvmp
docker compose -f deploy/docker/docker-compose.yml up -d

# Revert Nginx upstream
sudo nano /etc/nginx/sites-available/mvmp.conf
# Change back to 127.0.0.1:3001 and 127.0.0.1:3005
sudo nginx -t && sudo systemctl reload nginx
```

Public traffic returns to Docker. The Docker data volumes were never touched (only stopped). No data loss.

## Appendix — Common pitfalls

### AI provider keys fail to decrypt

**Cause**: `AI_ENCRYPTION_KEY` in Native `/etc/mvmp/app.env` doesn't match Docker's.

**Fix**:
```bash
sudo grep AI_ENCRYPTION_KEY= /opt/mvmp/.env   # Docker's key (still on disk)
# Copy that exact value to:
sudo nano /etc/mvmp/app.env
# Set AI_ENCRYPTION_KEY=<Docker's value>
sudo systemctl restart mvmp-api mvmp-worker
```

### Sessions invalidated after migration

**Cause**: `SESSION_SECRET` differs between Docker and Native.

**Fix**: Use the same `SESSION_SECRET` value. Sessions stored in the `Session` table are not signed (just UUIDs), so this is only a concern if you've enabled signed cookies in a future MVMP version.

### Prisma migration fails

**Cause**: The Docker backup includes `_prisma_migrations` rows that conflict with Native's `prisma migrate deploy`.

**Fix**: The `restore.sh` script excludes `_prisma_migrations` from the dump (see `backup.sh` line `--exclude-table-data='_prisma_migrations'`). If you used a different backup method, you may need to truncate that table:

```bash
sudo -u postgres psql -d mvmp -c "TRUNCATE _prisma_migrations;"
sudo bash scripts/deploy/migrate.sh
```

### Nginx config has both upstreams

If the host had Docker's Nginx config and you switched to Native's, make sure the upstreams are correct. The Phase 13 `setup-nginx.sh` writes a config pointing at Native ports. Verify:

```bash
sudo grep -E "server 127.0.0.1" /etc/nginx/sites-available/mvmp.conf
# Should show :3000 and :3003 (Native), not :3001 and :3005 (Docker)
```
